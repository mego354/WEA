### 2. البنية الموحدة المنفذة (Canonical Shared Architecture)
تم بناء مكون واجهة موحد وشامل في:
[`templates/components/customer_selection_modal.html`](file:///c:/D/Cooding/GENERAL/new/ERP/templates/components/customer_selection_modal.html)
تم تضمينه مركزياً في [`templates/layouts/base.html`](file:///c:/D/Cooding/GENERAL/new/ERP/templates/layouts/base.html)، مما يجعله متاحاً بشكل معياري وموثوق عبر جميع صفحات النظام.

#### مكونات النموذج المشترك:
1. **شريط العنوان (Modal Header)**:
   - يتغير تلقائياً حسب وضع الاستدعاء:
     - `mode = 'unplanned_visit'`: يعرض عنوان **"زيارة خارج الخطة"** مع أيقونة `room`.
     - `mode = 'add_to_plan'`: يعرض عنوان **"إضافة عميل إلى الخطة"** مع أيقونة `event_available`.
   - زر الإغلاق السريع (`close`).
2. **محرك البحث الحي (Debounced Typeahead Search)**:
   - حقل إدخال يحمل تسمية `عميل *` مع placeholder `بحث بالاسم أو الكود...`.
   - تأخير بمقدار 250ms مع مؤشر تحميل تفاعلي (`#unified-search-spinner`).
   - استعلام فوري لنقطة النهاية المؤمنة [`/contacts/api/search/?q=`](file:///c:/D/Cooding/GENERAL/new/ERP/contacts/views.py#L948-L1040).
   - عرض قائمة النتائج المطابقة متضمنة:
     - أفاتار دائري بالأحرف الأولى للعميل (`avatar initials`).
     - كود واسم العميل بصيغة `[Code] Name`.
     - شارة تصنيف العميل (`عميل` / `A` / `منظمة`).
     - التخصص والمنطقة (`Specialty • Area`).
     - مؤشر حالة إحداثيات GPS (`pin_drop` للعملاء ذوي الموقع المسجل، أو `location_off`).
3. **بطاقة ملف العميل المختار (Customer Dossier Card)**:
   - تظهر فور اختيار العميل وتخفي حقل البحث:
     - الأفاتار، الكود، الاسم الكامل، شارة نوع جهة الاتصال (`شخص` / `منظمة`)، وتصنيف العميل.
     - التخصص والمنطقة المعتمدة.
     - مؤشر فحص الموقع الجغرافي المسجل للعميل.
     - زر الاتجاهات (`directions`): يفتح مسار الملاحة عبر خرائط جوجل في نافذة جديدة.
     - زر المعاينة (`معاينة`): يفتح ملف العميل الكامل في تبويب جديد.
     - زر `تغيير العميل`: يعيد فتح حقل البحث للبحث عن عميل آخر بسلاسة.
4. **محدد قالب الزيارة (Template Selector)**:
   - قائمة منسدلة لقوالب الزيارات المحملة من [`/activities/api/templates/`](file:///c:/D/Cooding/GENERAL/new/ERP/activities/views.py#L482-L487).
   - خيار افتراضي: `اختر قالب الزيارة`.
5. **سياق خطة الزيارات (Planned Visit Context)**:
   - يظهر فقط عند استدعاء النموذج من خطة الزيارات (`add_to_plan`):
     - التاريخ المحدد في الخطة (`date`).
     - ملاحظات التخطيط (`notes`).
     - معرف المندوب المسئول (`assignee_id`).
6. **زر الإجراء الأساسي (Submit Action)**:
   - لزيارة خارج الخطة: `تسجيل الزيارة` -> يوجه مباشرة إلى نموذج الزيارة المعتمد [`/visits/create/?contact_id=...&template_id=...`](file:///c:/D/Cooding/GENERAL/new/ERP/activities/views.py#L725-L826).
   - لإضافة عميل للخطة: `إضافة إلى الخطة` -> يرسل طلب AJAX POST إلى [`/planned-visits/add-item/`](file:///c:/D/Cooding/GENERAL/new/ERP/activities/views.py#L489-L545) ويحدث جدول اليوم تلقائياً.

### 3. حفظ الفروق الوظيفية الجوهرية بين العمليتين
تم الحفاظ بدقة على المعنى التجاري المستقل لكل عملية وفقاً لقواعد العمل الصارمة:

| البعد التجاري | إضافة عميل إلى الخطة (Add to Plan) | تسجيل زيارة خارج الخطة (Unplanned Visit) |
| :--- | :--- | :--- |
| **الكيان المنشأ** | `PlannedVisitItem` مرتبط بـ `PlannedVisitDay`. | سجل زيارة ميدانية كامل `Visit` بحالة `finished`. |
| **حالة التنفيذ** | غير منفذة (`is_executed = False`). | منفذة ومسجلة (`status = 'finished'`). |
| **إلزامية الـ GPS** | غير مطلوب (لأنها عملية تخطيط مسبق لا تتطلب تواجد ميداني). | إلزامي للمندوب في الميدان مع التحقق من النطاق (300 متر). |
| **العينات وملاحظات الميدان** | غير متاحة في مرحلة التخطيط. | متاحة مع تسجيل أصناف العينات المجانية والتقييم. |
| **تدفق التحويل للتنفيذ** | زر `بدء الزيارة` ينقل المخطط إلى نموذج تسجيل الزيارة ويربط الـ `planned_item_id`. | تسجل فوراً كزيارة غير مخططة (`is_planned = False`). |

### 4. نقاط الدخول المشتركة واختباراتها
تم توحيد جميع نقاط الدخول في النظام لتمر عبر نفس المكون البرمجي:
1. **الزر العائم FAB - الخيار الأول**: يفتح النافذة بعنوان "زيارة خارج الخطة".
2. **شريط كروت أيام خطة الزيارات**: زر "إضافة عميل لخطة هذا اليوم" يفتح نفس النافذة بتاريخ اليوم المستهدف.
3. **درج تنقية العملاء الجانبي**: زر الإضافة السريع بجانب كل عميل يفتح النافذة مع اختيار العميل مسبقاً.
4. **ملف العميل Dossier**: أزرار بدء الزيارة أو جدولتها تمر عبر نفس مسار الربط الموحد.

### 5. التحقق الآلي وفحص التكرار (Anti-Duplicate & Validation)
- التحقق من اختيار العميل على الواجهة والخادم.
- منع إضافة نفس العميل مرتين لنفس يوم الخطة مع إظهار رسالة واضحة: `العميل ... مضاف بالفعل لخطة يوم ...`.
- منع تسجيل زيارة مكررة لنفس العميل والمندوب خلال 60 ثانية.
- جميع اختبارات الوحدة والتكامل في `activities/tests.py` اجتازت بنسبة **100% نجاح (24/24 اختبار)**.
